# 动态规划

**动态规划** (Dynamic Programming, DP) 是一种通过把*原问题分解为相对简单的子问题*的方式求解复杂问题的方法。它使用**状态**来描述子问题，通过**状态转移**家里子问题之间的依赖关系，并保存已经计算的结果，避免相同的子问题被反复求解。

由于动态规划并不是某种具体的算法，而是一种解决特定问题的方法，因此它会出现在各式各样的数据结构中，与之相关的题目种类也更为繁杂。

> [!note] 动态规划与贪心算法
> 动态规划和贪心都是将问题分解为子问题求解的方式。在最优化问题中，动态规划通常比较多个候选决策对应的子问题结果，而贪心则直接做出某个局部选择。贪心算法的一个重要的特点就是，需要证明这个局部选择不会妨碍后的全局最优解。
>
> 动态规划一般无法证明一个状态是否可以被安全的丢弃，因此需要将该状态存储下来，在未来需要的时候再进行访问。

> [!note] 动态规划与分治算法
> 另一个从子问题角度考虑的算法思想是**分治**。典型的分支算法，例如归并排序，产生的子问题是不会重复出现的。而动态规划则着重处理**重叠子问题**，使得一个子问题的结果可以被后续计算重复使用。

## 算法思路

动态规划问题的状态定义和转移方式十分灵活，因此很难用一份固定的代码解决所有的问题。不过，可以采用一个相对比较通用的推导流程，使得我们可以准确的分析动态规划的问题，并在合适的位置正确的处理边界。本文采用下面的逻辑来陈述动态规划算法的思考逻辑：
1. **记忆化搜索**：子问题是什么，怎么缩小它？
2. **转换为递推**：这些子问题应该按照什么样的顺序计算？
3. **滚动优化**：哪些结果需要保留，哪些空间可以复用？

### 记忆化搜索

动态规划问题的分析推荐从记忆化搜索开始。所谓记忆化搜索，就是**搜索**加上**记忆化**，这是两个概念。其中，搜索就是常见的暴力遍历所有可能的情况，不过能够记忆的搜索需要是**无状态的**。

> [!note] 无状态
> `dfs` 函数必须不依赖任何外部变量，只要输入数据不变，则输出的结果确定。对于一个无状态的函数，只要我们知道它的输入，那么它的输出就是确定的。我们可以用一个 `memo` 数组记录该函数的输出，并用对应的输入作为下标。这样，当我们在运行函数之前，我们可以先访问一下 `memo` 数组，如果其中已经记录了结果，那么我们就不需要再运行一次 `dfs` 搜索函数，直接取 `memo` 中的结果返回即可。
>
> 在 Python 中，我们可以为一个函数添加 `@cache` 装饰器来实现这个功能。

```cpp
// 这里给出 cpp 的记忆化搜索代码，这有助于我们理解
class Solution {
  public:
	int method(vector<int>& nums) {
		int n = nums.size();
		vector<int> memo(n, -1); // 记忆数组
		auto dfs = [&](this auto& dfs, int i) -> int {
			// 这是递归搜索函数，其中可能会基于当前的状态进行各种各样的计算
			// 通常，我们会思考，当其他位置的结果已知时
			// 我们是否可以直接推导到当前的状态？
			if (i == 0) { // 递归边界
				return nums[0];
			}
			if (i < 0) {
				return 0;
			}
			// 如果 memo 不是 -1 则返回 m
			int& m = memo[i];
			if (m != -1) return m;
			return m = max(dfs(i - 1), dfs(i - 2) + nums[i]);
		}
	}
};
```
